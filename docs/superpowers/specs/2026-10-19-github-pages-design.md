# 插件 GitHub Pages 官网设计

## 目标与范围

面向寻找 Spring Boot 本地启动工具的 DSH 开发者，提供中文单页官网，让访客了解插件定位、看到真实界面并找到安装命令。页面不连接本机 DSH，不提供实际服务启停，不修改插件运行代码。

用户已确认 GitHub Pages、浅色技术风格、Spring 绿点缀、纯静态且无需构建的方向。本次是新增独立网站入口，采用设计文档与实施计划流程；在当前干净工作树开发，不新建 worktree。

## 技术选择

- 使用原生 HTML、CSS、少量 JavaScript，源码放在 `website/`。相较前端框架，无额外依赖、构建或运行服务；相较 README，具有独立导航和安装交互。
- GitHub Actions 使用官方 Pages 上传与部署流程，仅上传 `website/`。与现有插件测试工作流分离，不上传仓库、测试夹具或本机配置。
- 预期地址：`https://simplifyOurLife.github.io/dsh-spring-boot-launcher/`；实际是否启用 Pages 和部署成功须单独核验，不能以文件已提交代替上线成功。
- 所有站内资源使用相对路径，适配仓库子路径部署；不使用第三方字体、追踪脚本或统计服务。

## 页面结构与视觉

1. 顶部导航：功能、安装、兼容性、GitHub；移动端允许换行，避免额外菜单组件。
2. 首屏：产品名、Spring Boot（SpringBoot）专用启动器定位、简短价值说明；提供“安装插件”和“查看源码”入口。
3. 界面展示：复用 `docs/images/spring-boot-services-panel.png`，在站点资源目录保存副本并标注为界面示例，不伪装为在线控制台。
4. 功能：Maven 项目发现、Profile 选择、集中启停、日志搜索与跟随。说明搜索、向上滚动和切换服务会退出跟随。
5. 安装：完整安装命令、复制按钮、重启 DSH 的提示与市场入口；更新操作链接到仓库说明，不编造宿主按钮或 CLI 参数。
6. 兼容性与安全：Windows 11、PowerShell 7、Maven Spring Boot；Gradle 不支持，Linux/macOS 未验证，桌面端适配不等于真实工程全流程验收。只运行可信项目和 JDK，日志可能含敏感信息。
7. 页尾：版本记录、问题反馈、Apache-2.0 协议链接。

以偏白背景、深色文字、Spring 绿强调和紧凑代码面板形成开发者工具风格。主内容使用适度留白与清晰层级，不堆叠营销卡片、不夸大成熟度。桌面与手机均可阅读；图片等比缩放，命令区域可横向滚动。

## 内容与交互约束

- 标题、介绍与页面元数据同时出现 Spring Boot / SpringBoot，覆盖自然搜索写法；官网优化不能替代市场收录条目的别名修改，本轮不自动提交市场 PR。
- 安装命令来自现有 README：`dsh plugin --profile web add github:simplifyOurLife/dsh-spring-boot-launcher`。
- 点击复制后反馈成功；剪贴板 API 不可用或被拒绝时，提示手动选择命令复制，不虚报成功。
- 使用普通锚点完成导航，JavaScript 关闭时仍能阅读和手动安装。复制状态使用可访问的提示区域，按钮有键盘焦点样式。
- 版本入口链接 GitHub Releases，不请求在线 API 或硬编码“最新版本”；Alpha 与兼容性说明以实施时仓库文档为依据。

## 文件与部署影响

新增 `website/index.html`、样式、交互脚本、截图资源、`.nojekyll`，以及独立的 Pages 工作流；在 README 增加官网入口。是否已上线须明确标注。不新增 npm 运行依赖，不执行前后端 build，不改变插件发行包的显式文件清单。

部署工作流限制为默认分支中官网资源或工作流自身变更，以及手动触发；权限限定为读取内容、写 Pages 和申请身份令牌。首次启用 Pages 若需要额外仓库设置权限，应准确报告，不擅自调整仓库可见性或域名。

## 验收与回退

- 检查页面必需文案、安装命令、站内资源路径和外链目标；确认网站文件未进入插件发行包。

- 运行与改动相关的测试，不执行 build；部署后检查 Actions 结果和真实 Pages 地址。
